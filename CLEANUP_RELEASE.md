# Website cleanup release

The full sibling-service rollout, rollback, read-only diagnostics and pilot acceptance checklist is in `call_agent/CLEANUP_RELEASE.md` in the parent workspace. This repository remains independently deployable.

Apply additive migrations `003_action_requests.up.sql` and `004_ingestion_status.up.sql` after existing migrations 001/002, through the authorized operator process. Never apply them automatically on request. 003 stores request hashes/action receipts in the existing admin database; call_agent needs a restricted database connection. 004 adds document processing state. Roll back code/configuration while retaining both structures and their data; no destructive down migration is supplied.

`voice_agent_admin.business_settings` is the shared business-settings source, falling back to website environment defaults before the first save. `/api/internal/business` requires a separate server `BUSINESS_CONFIG_KEY` of at least 32 characters and returns business ID, settings version, assembled instructions and greeting. Configure call_agent's HTTPS `BUSINESS_CONFIG_URL` and matching key to use this for phone/standalone browser sessions. Browser offers carry server-loaded settings and `BUSINESS_ID`; call_agent checks its configured scope. Prompt text cannot enable capabilities or choose a tenant. Existing authenticated per-channel overrides remain, and existing sessions retain their snapshots. Local environment files still say `BUSINESS_ID=primary`; align that explicitly with the intended deployment (the existing voice workflow/wrapper use `jayeola`) before rollout.

Optional `INGESTION_SERVICE_URL` and `INGESTION_API_KEY` connect newly uploaded bytes to the existing ingestion API with a stable source ID. Configure the ingestion service's fixed `INGESTION_COMPANY_ID` to match. The server first records processing in an atomic dispatch claim. Success sets internal indexed state; missing/failed/uncertain response never simulates completion. No ingestion connection means uploaded only. Repeated upload keys cannot blindly retry processing after timeout. A new file selection creates a new source, including for the same name.

Document listing reports searchable only after successful ingestion and an authenticated `/sources/{source_id}` check on the configured rag-wrapper, with a matching Dropbox revision. It otherwise reports uploaded, processing, failed or unverified. Retrieval unavailable means availability is unverified. The wrapper uses its configured table and trusted tenant; the website cannot select one. Dropbox deletions do not delete vectors, and the existing Google Drive n8n trigger does not watch Dropbox. No replacement/deletion API was added; reconcile uncertain processing and source retirement through the existing operator process. Before migration 004, upload/listing remain available with uploaded-only status and direct ingestion dispatch stays disabled; apply 004 to enable processing tracking.

Default `VOICE_BACKEND=pipecat` uses call_agent duration, inactivity and process-local admission controls on both browser and telephone. `openai_direct` is the retained read-only website rollback; it does not change phone routing and does not use call_agent admission limits. Keep Pipecat for the controlled pilot. Website admin/auth request limits use PostgreSQL buckets.

Customer details may be processed by OpenAI/Twilio, stored in n8n memory/execution data, and after confirmation saved to the existing Google Sheet and sent to the configured Telegram destination. Dropbox stores business documents; vectors contain extracted content/metadata. The website adds no transcript/audio persistence. Configure access/retention at each provider; do not promise zero retention. Credentials remain server-only.

Before a pilot, verify a new browser and phone greeting, snapshots across settings edits, rejection of a mismatched business, pricing with no writes, confirmation/refusal and actual action receipts in staging, capacity before phone media starts, and uploaded/processing/searchable/failed against actual source visibility.
